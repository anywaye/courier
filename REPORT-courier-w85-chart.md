## The generator bug — `application.yaml`

**File:** `caf/internal/gen/chart.go`, lines 407-441 (`renderApplication`)
**Emitted path:** `chart/templates/application.yaml`

The generator emits an Argo `Application` whose source is a **git**
repo:

```yaml
spec:
  source:
    repoURL: git@github.com/cafaye/courier.git
    targetRevision: {{ .Values.targetRevision }}
    path: chart
```

But the substrate **already owns courier's `Application`** in
`kit/templates/substrate/manifests/applications/courier.yaml`, and that
one uses an **OCI** chart source:

```yaml
spec:
  source:
    repoURL: oci://ghcr.io/cafaye/charts
    chart: courier
    targetRevision: 0.1.0
```

Two `Application`s named `courier` in `argocd` fight each other — split
brain. The substrate's is the one `install.sh` applies
(`install_applications()` → `kubectl apply -f "$MANIFEST_DIR"`), and
`DEPLOYMENT.md` decides the OCI design (private registry + read-only
pull secret, because the fleet is closed source and a customer must
pull the chart without read access to the source repos). The generated
one was **deleted**, not ignored. Gateway's landed chart (W67) ships no
`application.yaml` either.

**Follow-up caf packet must fix the generator to stop emitting it.**

## values.yaml adjustments

| value | generator default | courier value | why |
|---|---|---|---|
| `service.port` | 80 | 4000 | must match the container port the generator baked into the Deployment (4000, from the Elixir language table) |
| `env` | `{}` | `PORT: "4000"` | non-secret; the app reads it |
| `image.tag` | `"0.1.0"` | `"0.1.0"` | unchanged — a value, never `latest` |
| `secretName` | `courier-secrets` | `courier-secrets` | unchanged — secrets by reference via `envFrom` |
| `resources` | 100m/128Mi → 500m/512Mi | unchanged | DEPLOYMENT.md sizes the box at 8GB comfortable |

Secrets are **referenced by name, never inlined**: the Deployment reads
`courier-secrets` with `envFrom: secretRef`, and `values.yaml` documents
which keys the secret must contain (`DATABASE_URL`, `SECRET_KEY_BASE`,
`COURIER_IDENTITY_TOKEN`, `COURIER_SECRET_BOX_KEY`, `COURIER_SMTP_USERNAME`,
`COURIER_SMTP_PASSWORD`, `COURIER_INBOUND_RESEND_SECRET`,
`COURIER_ERROR_RELAY_TOKEN`). No credential appears in `values.yaml`.

```
$ helm template courier ./chart
---
# Source: courier/templates/service.yaml
apiVersion: v1
kind: Service
metadata:
  name: courier
spec:
  type: ClusterIP
  ports:
    - name: http
      port: 4000
      targetPort: http
      protocol: TCP
  selector:
    app.kubernetes.io/name: courier
    app.kubernetes.io/instance: courier
---
# Source: courier/templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: courier
spec:
  replicas: 1
  template:
    spec:
      imagePullSecrets:
        - name: courier-ghcr
      containers:
        - name: courier
          image: "ghcr.io/cafaye/courier:0.1.0"
          imagePullPolicy: IfNotPresent
          ports:
            - name: http
              containerPort: 4000
              protocol: TCP
          envFrom:
            - secretRef:
                name: courier-secrets
          env:
            - name: PORT
              value: "4000"
          readinessProbe:
            httpGet:
              path: /readyz
              port: http
            initialDelaySeconds: 5
            periodSeconds: 10
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
            limits:
              cpu: 500m
              memory: 512Mi
```

`kubectl apply --dry-run=client` requires a live cluster for API
discovery; without one it fails with `connection refused` on
`localhost:8080`. The `helm template` output above is the render proof.
